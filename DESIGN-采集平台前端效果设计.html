2多租户隔离（本期核心）

架构定案：全链路加 tenant_id。前端体现三件事——租户级数据隔离、跨租户身份切换、L0 管理员全局视角。

业务场景

租户运维 航企A 登录
只看到航企A的 SAgent、指标、任务、权限、审计
右上角可切换到其在多租户名下"已获授权"的其它租户（如 A 集团下属 B 航司）
切换即换 token（BOMC7.0 JWT 含 tenant_id），前端整页刷新隔离，URL 携带租户态
架构依据：决策 D3「多租户本期做」——DB 表带 tenant_id，API 强制租户过滤（防跨租户注入被拒），前端菜单与数据随 token 权限渲染。

交互与校验点

L0 管理员
进入"租户与权限"，创建租户、分配用户、映射角色→功能
设置每个租户的可见资源池范围
审计日志中按 tenant_id 检索各租户操作
测试跨租户查询（用 A 的 token 查 B 的数据）→ 界面明确弹出"权限拒绝"
安全演示用例：admin 尝试跨租户取数，系统拒绝并记录审计。这条是"安全合规"验收的关键交互。

3资源与接入（标准化 · 三步向导）

主机/PaaS 接入统一为可视化三步：选目标 → 选能力 → 预演影响。vmauth 收口保证目标机 curl 不暴露采集数据。

接入向导（分步）

① 选资源对象→ ② 选采集能力→ ③ 预演影响 & 提交
步骤界面交互后端依据
① 选对象资源目录勾选多台主机/中间件，自动获得资源唯一编码catalog / resource_id
② 选能力host_metrics · mysql · redis · OTel · 脚本等；填连接与采集间隔onboard/abilities
③ 预演影响展示将在一批 L1 分发的包、资源/端口占用、匹配版本，diff 后确认version_match

目标主机安全（vmauth 单端口）

目标主机：vmauth 单端口 :9443
/node-metrics ✓/mysql-metrics ✓/redis-metrics ✓
未带 auth_key 的 curl/扫描 → 401，返回空
架构 D4：对外只暴露 1 个受鉴权端口，按 path 路由各 Exporter；覆盖远程 PaaS。前端在"详情"展示端口收敛校验结果。
接入后的界面反馈（闭环确认）
SAgent 注册+心跳→ Exporter 启动→ vmauth 收口→ vmagent 经 vmauth scrape→ remote write 入库→ 证据链全绿 + 指标可查

4采集健康 · 证据链与断采管控

不满足于"online 绿点"。每个采集目标呈现五段证据链与新鲜度，断采自动匹配固化处置场景，自动处置失败转人工一键处置。

人工兜底：一键处置

运维收到升级告警
打开断采事件，查看检测方式、影响范围、证据链

接管准则：组件故障接管需连续 N 检测周期确认，界面显示"确认中·避免瞬时抖动漂移"。

5变更中心 · 版本升级与 Exporter 漂移

对应场景十三/十四 + 架构 3.1-C（故障漂移）。面向批量灰度、就近取包、失败自动回滚、Exporter 归属迁移。

版本升级（L1 四进程 + Package Cache 就近取包）

L0 上传新版→ 同步各 L1 Cache(就近)→ 灰度批次 10% / 观察 / 继续→ SAgent 升级失败自动回滚
界面元素交互
批量进度条分池分策略展示灰度水位，可暂停/继续/终止
版本兼容矩阵所选 新版本 × 目标 host exporter 版本 匹配，不匹配禁止升级
就近取包状态每台 L1 Cache 显示同步进度与校验和（风险A红线）
回滚面板升级失败自动 rollback，界面显示回滚后版本与数据补建状态

Exporter 故障漂移（前方可视）

mysql-A exporter 探活失败（连续 N 周期）
界面标记 Exporter 降级，展示主备关系
L0 决策归属迁移 → control 通道下发新配置到健康 L1
迁移完成，界面展示"采集归属已切换"与幂等确认
ui 全程可观察：谁接管了、是否重复拉起

7用户故事与角色

三个核心角色：L0 平台管理员（跨租户全局治理）、租户运维（本租户采集运维）、只读观察者/第三方订阅（数据消费）。

角色用户故事（As a … I want to … So that …）
L0 管理员作为平台管理员，我想要在统一控制台创建/停用租户并分配资源池与角色，以便隔离各租户的采集数据与权限。作为管理员，我想要查看全网告警与容量水位，以便在 Gateway 连接数逼近 9k 前主动扩容，避免采集降级。
租户运维作为租户运维，我想要用三步向导把一台新主机纳入采集，以便秒级看到它进入证据链并采集到指标。作为租户运维，我想要在某 Exporter 故障时看到"逐段归因 + 一键处置 + 恢复验证"，以便快速恢复采集而不是靠猜。作为租户运维，我想要在版本升级时看到灰度进度与自动回滚，以便批量升级不中断采集。作为租户运维，我想要自定义本租户仪表板，以便我团队关键指标一屏可得。
只读观察者作为只读用户，我想要按四维授权（指标×租户×形态×时间）订阅部分指标，以便安全地消费开放数据而不越权。
安全合规者作为审计员，我想要按操作人/时间/目标/类型检索审计日志（保留 180 天、只追加不可改），以便追溯任何变更来源，验证跨租户越权被拒绝。
